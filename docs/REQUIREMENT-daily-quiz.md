# 每日智能练习 (Daily Smart Quiz) 需求文档

> Feature ID: F012 | 版本: v1.0 | 创建日期: 2026-06-07

## 1. 背景与目标

### 1.1 业务背景

当前 Med-Recallix 的做题模块（Quiz / Exam）均为**用户主动触发**，存在以下问题：

1. **缺乏固定节奏**：用户没有"每日打卡"的仪式感，容易断学
2. **高频错题无闭环**：错题本存在但未与后续练习联动，错误知识点无法被反复强化
3. **被动提醒不足**：现有 Dashboard 仅展示复习数量，缺少主动推题机制
4. **Quiz/Exam 入口较深**：Quiz 不在底部导航，Exam 入口在知识点页，用户发现率低

### 1.2 目标

| 维度 | 目标 | 衡量指标 |
|------|------|----------|
| **业务目标** | 提升用户日活与做题频率 | 日均做题数 ≥ 30 题/人 |
| **用户目标** | 每天都有"刚好够做"的题量，无需思考今天做什么 | 完成率 ≥ 60% |
| **产品目标** | 高频错题自动进入下一轮练习，形成"做题→纠错→再练"闭环 | 错题重现命中率 ≥ 40% |

### 1.3 产品定位

> 每日智能练习 = **定时出题** + **冒泡提醒** + **错题驱动** 的主动式学习推动器

## 2. 用户与角色

| 角色 | 描述 | 诉求 |
|------|------|------|
| 备考者 | 日常使用 Med-Recallix 的医考备考用户 | "打开就有题做，不用想今天学什么" |
| 系统调度器 | 后台定时逻辑 | 每日凌晨为每位用户生成当日题目集 |
| AI 伙伴 | 人格化 AI | 通过冒泡/弹窗督促用户做题 |

## 3. 功能需求

### 3.1 User Stories

#### US-012-1: 系统每日自动生成个性化题目集

**优先级**: P0
**描述**: 作为备考者，我希望每天打开应用就有一套为我准备好的题目，无需手动选题。

**验收标准**:
1. Given 每日首次访问应用, When 题目已生成, Then 可直接进入答题
2. Given 用户有历史错题, When 生成题目, Then 错题重现比例 ≥ 40%
3. Given 用户无任何知识点, When 生成题目, Then 使用系统默认题库或提示先添加知识点
4. Given 生成过程中 AI 失败, When 部分题目生成成功, Then 先展示已生成的部分，后续补全

#### US-012-2: 冒泡提醒用户做今日练习

**优先级**: P0
**描述**: 作为备考者，如果我进入应用但忘记做题，系统应温和但持续地提醒我。

**验收标准**:
1. Given 用户登录且当日未做题, When 进入任意页面, Then 底部冒泡提醒"今日练习已就绪"
2. Given 用户忽略冒泡, When 10分钟后仍未做题, Then 再次弹出冒泡提醒
3. Given 用户点击"开始做题", When 进入做题页, Then 冒泡消失且不再弹出（当日）
4. Given 用户点击"稍后再做", When 关闭冒泡, Then 10分钟后再次弹出
5. Given 用户已完成当日练习, When 后续访问, Then 不再弹出提醒

#### US-012-3: 做题流程与结果反馈

**优先级**: P0
**描述**: 作为备考者，我希望做完题后能看到清晰的对错统计和解析。

**验收标准**:
1. Given 用户开始做每日练习, When 答完所有题, Then 展示答题报告（正确率/用时/弱项）
2. Given 答题报告页, When 有错题, Then 可一键查看错题解析
3. Given 答题完成, When 返回首页, Then Dashboard 展示当日做题进度
4. Given 用户只做了部分题, When 中途退出, Then 保存进度，下次可继续

#### US-012-4: 错题驱动的智能出题

**优先级**: P0
**描述**: 作为备考者，我希望之前做错的题目能够以变形/类似的方式再次出现。

**验收标准**:
1. Given 用户有错题记录, When 次日生成题目, Then 至少 40% 题目基于高频错题知识点
2. Given 某知识点错 ≥ 3 次, When 生成题目, Then 该知识点必定出现在次日题目中
3. Given 错题被连续答对 2 次, When 生成题目, Then 降低该知识点的出现权重
4. Given 用户全部错题已攻克, When 生成题目, Then 回归正常分布（按知识点覆盖度）

#### US-012-5: 在学习统计中展示每日练习数据

**优先级**: P1
**描述**: 作为备考者，我希望在统计页看到每日练习的完成情况和进步趋势。

**验收标准**:
1. Given 用户在统计页, When 查看每日练习板块, Then 展示连续完成天数、正确率趋势
2. Given 有多日数据, When 查看趋势图, Then 展示近 7/30 日正确率折线图
3. Given 用户某天未完成, When 查看统计, Then 该日标记为"未完成"而非断签

## 4. 详细交互设计

### 4.1 每日题目生成策略

```
┌─────────────────────────────────────────────────────────────────┐
│                   每日 50 题生成规则                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  ┌──────────────┐     ┌──────────────┐     ┌──────────────┐    │
│  │ 错题强化区    │     │ 薄弱知识区    │     │ 新知识区      │    │
│  │   20 题      │     │   15 题      │     │   15 题      │    │
│  │  (40%)       │     │  (30%)       │     │  (30%)       │    │
│  └──────────────┘     └──────────────┘     └──────────────┘    │
│                                                                  │
│  来源：高频错题        来源：SM-2 efactor    来源：未覆盖的       │
│  知识点的变形题        < 2.0 的知识点        知识点              │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

**生成规则细节**：

| 题区 | 比例 | 选题逻辑 | 题型 |
|------|------|----------|------|
| 错题强化区 | 40%（20题） | 取错误次数 Top-N 的知识点，AI 重新出题（换角度/换选项） | A1/A2 选择题 |
| 薄弱知识区 | 30%（15题） | 取 SM-2 efactor < 2.0 且 repetition ≥ 1 的知识点 | A1/A2 选择题 |
| 新知识区 | 30%（15题） | 取从未出题或复习次数最少的知识点 | A1/A2 选择题 |

**特殊情况处理**：
- 知识点 < 10 个：按实际数量生成，最少 10 题
- 无错题记录：错题区比例分配给薄弱区和新知识区（各 50%）
- AI 生成失败：降级为从历史题库中抽取已缓存题目

## 5. 每日题目生成时机

### 5.1 触发策略（无 Cron 方案）

由于 EdgeOne Pages 不支持传统 Cron Job，采用**客户端触发 + 服务端缓存**策略：

```
方案：Lazy Generation（惰性生成）

触发时机：用户当日首次访问时
│
├── 检查 KV 中是否已有当日题目集
│   ├── 有 → 直接返回
│   └── 无 → 触发生成
│       ├── AI 异步生成 50 题（约 10-30s）
│       ├── 前端展示 "正在为你准备今日练习..."
│       └── 生成完成 → 写入 KV → 通知前端
│
存储键: daily_quiz_{userId}_{date}
过期策略: 保留 7 天历史
```

### 5.2 为何选择惰性生成

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| Cron 定时生成 | 用户打开即可做题 | EdgeOne 不支持 Cron；需外部触发 | ❌ 不适合 |
| 客户端定时触发 | 简单 | Service Worker 不可靠 | ❌ 不可靠 |
| **惰性生成** | 无需 Cron；按需生成节省资源 | 首次打开需等待 | ✅ 采用 |
| 外部 Cron 服务 | 预生成 | 引入外部依赖 | 🔄 后续优化 |

### 5.3 生成性能优化

- **分批生成**：先生成 10 题让用户开始做，后台继续生成剩余 40 题
- **题目缓存**：历史生成过的题目存入 `quiz_cache_{userId}`，可快速复用
- **降级方案**：AI 不可用时，从缓存题目池随机抽取

## 6. 错题权重算法

### 6.1 权重计算公式

```
题目权重 = 错误次数 × 时间衰减系数 × 知识点重要度

其中：
- 错误次数: count(该知识点下的错题记录)
- 时间衰减系数: 1 / (1 + daysSinceLastError × 0.1)
  → 越近的错误权重越高
- 知识点重要度: 
  → SM-2 efactor < 1.5: 权重 ×2
  → SM-2 efactor 1.5~2.0: 权重 ×1.5
  → SM-2 efactor > 2.5: 权重 ×0.5
```

### 6.2 错题毕业机制

```
错题毕业条件：
- 连续 2 次答对同知识点的题目
- 且两次间隔 ≥ 2 天

毕业后：
- 该知识点从"错题强化区"移至"薄弱知识区"
- 权重降为原来的 30%
- 若再次答错，立即回到"错题强化区"
```

## 7. 数据模型设计（KV 结构）

### 7.1 新增 KV Key

| KV Key | 说明 | 生命周期 |
|--------|------|----------|
| `daily_quiz_{userId}_{date}` | 当日题目集（50题+状态） | 保留 7 天 |
| `quiz_progress_{userId}_{date}` | 当日答题进度 | 保留 7 天 |
| `quiz_result_{userId}_{date}` | 当日答题结果/报告 | 永久 |
| `error_weight_{userId}` | 各知识点错题权重索引 | 持续更新 |
| `quiz_cache_{userId}` | 历史题目缓存池 | 滚动 500 题 |

### 7.2 核心数据结构

```typescript
// 每日题目集
interface DailyQuizSet {
  id: string;
  userId: string;
  date: string; // YYYY-MM-DD
  status: 'generating' | 'ready' | 'in_progress' | 'completed';
  questions: DailyQuizQuestion[];
  generatedAt: string;
  completedAt?: string;
  totalCount: number;
  readyCount: number; // 已生成的题目数
}

// 单题结构
interface DailyQuizQuestion {
  id: string;
  stem: string;
  options: { label: string; content: string }[];
  answer: string; // "A" | "B" | "C" | "D" | "E"
  explanation: string;
  sourceKpId: string; // 关联知识点 ID
  sourceType: 'error_review' | 'weak_area' | 'new_coverage';
  userAnswer?: string;
  isCorrect?: boolean;
  answeredAt?: string;
}

// 错题权重索引
interface ErrorWeightIndex {
  userId: string;
  updatedAt: string;
  weights: {
    kpId: string;
    kpTitle: string;
    errorCount: number;
    lastErrorDate: string;
    consecutiveCorrect: number;
    graduated: boolean;
    weight: number; // 计算后的权重值
  }[];
}

// 每日答题结果
interface DailyQuizResult {
  userId: string;
  date: string;
  totalQuestions: number;
  correctCount: number;
  accuracy: number; // 0-100
  duration: number; // 秒
  weakCategories: { category: string; errorCount: number }[];
  comparedToYesterday: number; // 正确率变化百分点
  streak: number; // 连续练习天数
}
```

## 8. 非功能需求

| 维度 | 要求 |
|------|------|
| **性能** | 题目生成首批 10 题 < 15s；冒泡弹出延迟 < 100ms |
| **可靠性** | AI 不可用时有降级方案；进度不丢失 |
| **用户体验** | 冒泡不遮挡主要内容；做题页支持上下滑动切题 |
| **存储** | 单用户每日题目集约 50KB；7天历史 ≈ 350KB |
| **免打扰** | 22:00-07:00 不弹窗；已完成不再弹；最多6次/天 |

## 9. Scope 定义

### In Scope（本次做）

- 每日题目惰性生成引擎（50题，三区策略）
- 错题权重计算与毕业机制
- 底部冒泡提醒组件（10分钟间隔重弹）
- 每日练习答题页（顺序模式 + 进度保存）
- 答题报告页（正确率 + 错题分类 + 趋势对比）
- Dashboard 每日练习状态卡片
- Stats 页增加每日练习板块

### Out of Scope（后续迭代）

- Push 通知 / 微信服务号推送
- 外部 Cron 预生成（可考虑 CloudFlare Workers Cron）
- 自定义每日题数（固定 50 题）
- 多题型支持（A3/A4/B 型）
- 组队 PK / 排行榜
- 错题本导出 PDF
- 做题时间限制模式（模拟考试计时）

### 假设与依赖

| 类型 | 内容 |
|------|------|
| 假设 | 用户已有 ≥ 5 个知识点（否则提示先添加） |
| 假设 | AI API 大部分时间可用（≥ 95% 可用率） |
| 依赖 | 现有 Quiz 模块的 AI 出题 Prompt（可复用） |
| 依赖 | 现有错题本（wrong-answers）数据结构 |
| 依赖 | SM-2 Card 数据中的 efactor 用于薄弱判定 |
| 依赖 | Sonner Toast 组件（需启用）用于轻量通知 |

## 10. Edge Cases 与异常处理

| 场景 | 条件 | 期望行为 |
|------|------|----------|
| 知识点极少 | 用户仅有 1-4 个知识点 | 提示"添加更多知识点以开启每日练习"，暂不生成 |
| AI 完全不可用 | API Key 无效或网络断开 | 从历史缓存池抽题；若无缓存则展示"今日练习暂时无法生成" |
| 生成中途失败 | 已生成 30 题后 AI 中断 | 展示已有 30 题，标注"共 30 题（今日缩减版）" |
| 跨日做题 | 23:50 开始做，00:10 做完 | 算作开始日的练习；次日生成新题目集 |
| 多设备访问 | 设备 A 做到第 20 题，设备 B 打开 | 展示 KV 中的最新进度（第 20 题） |
| 连续弹窗关闭 | 用户连续 6 次关闭冒泡 | 当日不再弹出，改为 Dashboard 静态提示 |
| 前一天未做 | 昨日题目未完成 | 不延续到今日；今日生成全新题目；昨日标记"未完成" |
| 错题全部毕业 | 所有错题已攻克 | 错题区比例分配给新知识区 |

## 11. 验收标准（Definition of Done）

### P0 核心验收

- [ ] 用户当日首次访问时，系统在 15s 内生成首批 10 题可开始做
- [ ] 50 题中包含 ≥ 40% 基于错题知识点的题目（有错题时）
- [ ] 未做题时每隔 10 分钟弹出冒泡提醒（22:00-07:00 除外）
- [ ] 点击"开始做题"后当日不再弹出提醒
- [ ] 做题进度实时保存，退出后可从断点继续
- [ ] 答完全部题目后展示正确率、用时、弱项分析
- [ ] 错题自动计入权重索引，影响次日出题

### P1 增强验收

- [ ] Dashboard 展示"今日练习 X/50"进度卡片
- [ ] Stats 页展示每日练习正确率趋势图（7天）
- [ ] 连续练习天数（练习打卡 streak）正确计算和展示
- [ ] 冒泡文案池轮换（≥ 5 条不同文案）
